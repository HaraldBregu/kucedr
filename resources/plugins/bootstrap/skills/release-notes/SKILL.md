description: Turn a list of changes into short, user-facing release notes. Use when the user asks for release notes or a changelog entry.
---

# Release notes

1. Group the changes into **New**, **Improved**, and **Fixed**. Leave out empty groups.
2. Write one line per change, in plain language, describing what the user can now do.
3. Leave out internal refactors, dependency bumps, and test-only changes.
4. End with the version number and date if the user gave them.
