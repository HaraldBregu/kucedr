# Kucedr App Creator

Build a runnable, installable Kucedr app that uses only the SDK capabilities needed for the requested behavior. Keep the host boundary intact: the app is a sandboxed renderer and the Kucedr main process owns native access, credentials, and app identity.

## Establish the current contract

Before writing code, inspect the current SDK and app host contract:

- Read `packages/sdk/README.md` and `packages/sdk/index.ts` for supported public APIs and their types.
- Read the relevant interfaces in `src/shared/api_types.ts` when using a capability not covered by the README.
- Confirm the current manifest validation and import behavior in `src/main/apps/` if packaging, images, or window configuration matter.

Do not call undeclared preload globals or Electron/Node APIs from app renderer code. Import the public bridge from `@kucedr/sdk` instead.

## Create the app package

Create the source app in a separate project outside the Kucedr repository. Do not create a `resources/apps/` directory. The app folder name is the stable ID used for installation and persisted app data. Preserve an existing app ID unless the user explicitly requests a migration.

Include a production build and manifest:

```text
<app-id>/
├── manifest.json
├── package.json
├── src/
└── dist/index.html          # generated by the build
```

- `manifest.json` must provide `title`, `description`, and `metadata` with `version`, `category`, and `entry: "dist/index.html"`.
- Set `metadata.image` only to an app-owned raster asset accepted by the current manifest validator. Do not use SVG for this field.
- Use `window` only when the requested window dimensions or behavior differ from host defaults. Dimensions describe the outer window, including the host navigationbar.
- For local development, link `@kucedr/sdk` to this repository's `packages/sdk` using a path relative to the external app project. For a published app, use its released `@kucedr/sdk` dependency instead.
- Keep `package.json` metadata and `main` consistent with the manifest, even though the manifest takes precedence when both exist.

The imported bundle must contain the built entry. The importer copies the app without `node_modules`, retains the installed app's `data` directory when replacing the same ID, and rejects missing or invalid manifests/entries.

## Choose the SDK boundary deliberately

Embedded apps import from `@kucedr/sdk`:

```ts
import { agent, app, isKucedr, models, win } from '@kucedr/sdk';
```

Guard behavior that cannot work in a normal browser with `isKucedr()`. Use the typed API only for the requested capability:

- `app` provides theme/language state, approved app operations, and app-private storage.
- `agent` provides workspace operations and agent-run interaction.
- `models` performs configured model operations without exposing provider credentials.
- `win` provides the app window's approved native controls and context menu.
- `coding` and `terminal` are embedded-only, restricted capabilities. Use them only when the user specifically needs their workflows and the current host authorization supports the app.

For a separate process or external local client, use `connect()` with the SDK bearer token flow. It deliberately excludes app-private storage, `coding`, `terminal`, and embedded window controls; do not work around those exclusions.

## Treat data and UI as app-owned

Use `app.getAppStoreValue`, `setAppStoreValue`, and related methods for JSON-safe, non-secret state. Use the corresponding app-store file methods for binary or larger app-owned files. Never ask the app to supply an ID: Kucedr derives the namespace from the embedded calling view. Store paths must be safe relative forward-slash paths; do not pass absolute paths or traversal segments.

Use the host theme and language APIs where the feature needs them. Subscribe to change callbacks in React effects and always return the SDK unsubscribe function during cleanup.

Kucedr renders the native navigationbar. When the app needs navigationbar controls, call `win.setNavigationBarOptions()` with exported, allowlisted button icons and handle actions through `win.onNavigationBarButtonClick()`. Keep application state, including sidebar state, in the app; pass only the navigationbar descriptors and current sidebar layout information across the bridge.

## Verify the actual deliverable

1. Run the app's focused typecheck and production build using its declared scripts.
2. Confirm that `dist/index.html` exists and the manifest entry, image, and window settings pass the current validation rules.
3. When installation is in scope, import or refresh the built folder and verify the installed copy loads. Preserve existing `data` when replacing an app; source builds alone do not prove the installed artifact.
4. Exercise the requested SDK interaction inside Kucedr, including a no-host fallback when the app is expected to run in a browser preview.

Report the validation performed and any host-only behavior that could not be exercised.
